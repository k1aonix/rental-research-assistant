# 租房助手 · 单文件演示

上传文件：本目录 index.html，或 dist/index.html，两者内容相同。全部页面、样式和5套假数据都在这一个 HTML 内；本地用浏览器直接打开，无需服务器、代理或数据库。正式程序不受影响。

房源录入固定演示两轮：通勤目标附近5篇、地铁站周边5篇，共10篇虚构出租帖；其中5套进入候选，其余5套在历史中显示筛除原因。无需 API Key，六个调查阶段及正文/通勤/评论子状态都会播放并变绿，两轮完成进度也显示绿色。

## OpenRouter API Key

点击页面右上角“模型设置”，输入自己的 OpenRouter API Key，确认模型名称后点“应用设置”。Key 仅在当前页面内存中使用，不写入 HTML 或浏览器存储；刷新后需重新输入。“清除 Key”可立即恢复内置演示模式。

默认使用当前项目的智谱模型配置。不输入 Key 也可体验房源模拟调查和沟通样例。合同初始没有文档，点击上传合同后按当前候选的名称、费用、偏好和备注生成演示文档；合同检查始终在本地按规则生成，不调用 LLM，也不需要 Key。检查结合当前候选记录及现场待核实事项，若上传后费用改变会提示不一致；重新上传可载入最新费用，历史检查结果保留原样。

## 打包与更新

运行 python build_single.py（或 python build.py）重新打包。打包只读取本地配置中的模型名称，始终忽略 apiKey，不会把本地 Key 写进 HTML。

将本目录 index.html 替换 GitHub 仓库根目录 index.html 即可。只上传这个 HTML，无需上传整个 latest 文件夹。

## 验证

node single.test.cjs 检查本地打开、画像填写、地址确认、两轮进度和六阶段展示、五套候选、手机布局、模型设置输入和清除、模拟接口调用及刷新后不保留 Key。测试不消耗真实模型额度。
单帖输入会创建一套符合当前画像的独立演示房源，完成模拟调查后加入候选；相同链接复用该演示房源，不重复创建。自动搜索仍只处理原两轮各5篇样例。

GA4 埋点已按 UX Analysis.docx 接入，并已在 head 开头加入 GTM-EXAMPLE。线上网页会加载该容器，业务事件推入 dataLayer；仍需在 GTM 后台配置并发布 GA4 标签，网页接入不代表 GA4 已收到数据。本地 file:// 不加载容器。步骤与事件口径见 GA4_SETUP.md，配置文件为 analytics-config.json。

最新埋点：已识别现有 GA4 G-EXAMPLE000，业务事件使用 gtag 和 send_to 直接路由；包含失败、重试、首次成功及耗时参数。以 GA4_SETUP.md 最新说明为准。只替换 index.html 即可更新网页。

录入页已按 http://127.0.0.1:18082/ 的实际前端资源核对：使用正式样式，不额外添加绿色底色或完成边框。模拟步骤默认各停留600毫秒，单帖约5.4秒，两轮10帖约54秒；这些时长明确标为模拟，不是模型性能。progress.test.cjs 验证实际默认时序与 GA4 阶段开始/结束、耗时和一次完成事件。
